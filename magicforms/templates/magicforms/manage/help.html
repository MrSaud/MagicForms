{% trans "Overview" %}

{% blocktrans trimmed %} MagicForms has two sides: the public site (portals, live forms, and “track my submission” links) and the workspace (/manage/), where you define forms, workflow, print templates, and handle the inbox. Publishing checks that the form has at least one field and one workflow step. {% endblocktrans %}

  • {% trans "Home — list and search your forms, see high-level stats." %}
  • {% trans "Inbox — submissions waiting for an action on a step you can act on." %}
  • {% trans "Search — find submissions across your scope." %}
  • {% trans "New form / From text — create a blank form or draft fields from a description." %}

{% trans "Who can use the workspace" %}

{% blocktrans trimmed %} Superusers can manage every organization and use the Organizations area. Other staff only see data for organizations they belong to (memberships). If you are staff but see no forms, ask a superuser to add you to the right organization. Superusers can optionally narrow the visible organization list using “Organization scope” in the header. {% endblocktrans %}

{% trans "Building a form (A–Z)" %}

  1. {% trans "Create the form." %} {% trans "Use" %} {% trans "New form" %}{% if ai_features_enabled %} {% trans "or" %} {% trans "From text" %}{% endif %}. {% blocktrans trimmed %} Choose the organization and title (a URL path is created automatically from the title). Public URLs use your organization path and that path; you can require a secret share segment or query when configured in form settings. {% endblocktrans %}
  2. {% blocktrans trimmed %} Settings. Open Settings on the form: description, category, submission deadline, one-response-per-user, anonymous access, forwarding, public share key, hide from portal lists, print template files, and more. Turn on Published when the form is ready. {% endblocktrans %}
  3. {% blocktrans trimmed %} Logos (optional). Up to three images. Assign each to left, center (above the title), or right on the live form header. {% endblocktrans %}
  4. {% blocktrans trimmed %} Fields. Add questions with types such as short text, paragraph, email, number, date, dropdown, radio, checkbox, checklist, and file upload. Each field has an internal name (letters, numbers, hyphens): that name is what you use in print templates and APIs of merge. {% endblocktrans %}
  5. {% blocktrans trimmed %} Optional mapping. For signed-in users, a mapping name can pre-fill a field from the user account or HR profile (see the field help text in the editor for supported keys). {% endblocktrans %}
  6. {% blocktrans trimmed %} Sections. Group fields into collapsible sections on the public form if you want a long form to feel structured. {% endblocktrans %}
  7. {% blocktrans trimmed %} Workflow. Define ordered steps (labels and descriptions shown to applicants). Assign staff who may act while a submission sits on a step. Approvals move the submission forward; rejection stops it. You need at least one step before publishing. {% endblocktrans %}
  8. {% blocktrans trimmed %} Related forms (optional). Link a “child” form to a parent form so selected applicants can complete an extra questionnaire after the main submission. {% endblocktrans %}
  9. {% blocktrans trimmed %} Share. Use Share QR for the public URL. Applicants receive a private reference link to track status and download merged documents when you allow it. {% endblocktrans %}

{% trans "Print templates: DOCX, PDF, ODT" %}

{% blocktrans trimmed %} In form Settings, the primary print template can be a DOCX or a fillable PDF. When someone submits, MagicForms merges answers into that file for download or preview. An optional ODT file is for staff who prefer LibreOffice: answers are not merged into the ODT; use the DOCX or PDF field for merged outputs. {% endblocktrans %}

  • {% blocktrans trimmed %} DOCX uses Word with Jinja-style placeholders (via docxtpl). Use the same spelling as each field’s internal name; hyphens in names become underscores in the template context, and both forms are usually provided so either works. {% endblocktrans %}
  • {% blocktrans trimmed %} PDF uses AcroForm fields. Names should match internal field names; hierarchical field names from desktop tools are supported by matching the trailing segment. {% endblocktrans %}
  • {% if docx_pdf_available %} {% trans "This server can convert merged DOCX to PDF for in-browser preview when LibreOffice is configured." %} {% else %} {% trans "If the server is configured with LibreOffice, merged DOCX can be shown as PDF in the browser; otherwise only the DOCX download may be available for DOCX templates." %} {% endif %}
  • {% blocktrans trimmed %} Merged DOCX can be marked “read only” in Word for typical users (not cryptographic protection). For a format that is not meaningfully editable in Word, distribute PDF instead. {% endblocktrans %}

{% trans "DOCX and PDF placeholders" %}

{% blocktrans trimmed %} In DOCX, use Jinja syntax. For each form field, the merge context includes the field’s internal name and a Jinja-safe variant (hyphens and special characters mapped to underscores). Example for a field whose internal name is applicant-name: {% endblocktrans %}

{% verbatim %}
{{ applicant-name }}  or  {{ applicant_name }}
{% endverbatim %}

{% trans "Built-in string variables (same names in DOCX and PDF text fields):" %}

  • form_title, form_description
  • submitter_email, reference_token
  • submitted_at, current_step_label
  • workflow_timeline — {% trans "multiline history of events." %}
  • workflow_actions_summary — {% trans "short line of approve/reject actions." %}
  • workflow_comments — {% trans "all non-empty event messages." %}
  • workflow_last_action, workflow_last_comment
  • workflow_approver_signatures — {% trans "PDF text: lines noting approvals where the actor has a signature image on file." %}

{% blocktrans trimmed %} Checkbox values merge as “Yes” or “No”. File fields merge as the uploaded file name (or empty). {% endblocktrans %}

{% trans "Signatures in merged documents" %}

{% blocktrans trimmed %} Applicant and approver signature images are merged only in DOCX templates (as InlineImage). Variable names are fixed — they are not the labels users set on “My signatures”. PDF AcroForm merges are text-only; use workflow_approver_signatures or separate PDF fields for names and dates. {% endblocktrans %}

{% trans "Images and dates in Word" %}

  • {% blocktrans trimmed %} Use normal Jinja placeholders {{ variable }} for signature images and for dates. Dates are plain text (for example 2026-05-19 14:30), not RichText — do not use {{r ... }} for date fields unless you build RichText yourself in Python. {% endblocktrans %}
  • {% blocktrans trimmed %} No signature image on file: signature_primary or approver_signature_primary is filled with the submit or approval date only (no name, no “Approved:” label). Put names elsewhere (submitted_at, form fields, or row.label for approvers). {% endblocktrans %}
  • {% blocktrans trimmed %} Signature image exists: the primary placeholder is the image. Add a second line in your template for the date (see paste blocks below). Style that line in Word with a smaller font if you want a compact date under the image. {% endblocktrans %}
  • {% blocktrans trimmed %} signature_primary_date and approver_signature_primary_date are always set (submit date and first approver’s approval date). Use them on the line below the image; when there is no image, they match the same date as the primary placeholder. {% endblocktrans %}

{% trans "Respondent (applicant) variables" %}

  • signature_primary — {% blocktrans trimmed %} primary signature image from “My signatures” (lowest sort_order), or the submit date if no image. {% endblocktrans %}
  • signature_primary_date — {% blocktrans trimmed %}submit date/time; use on the line below the image.{% endblocktrans %}
  • signature_primary_fallback — {% blocktrans trimmed %}same submit date as plain text (handy if you branch in Jinja).{% endblocktrans %}
  • signature_primary_has_image — {% blocktrans trimmed %}True / False for conditionals.{% endblocktrans %}
  • submission_signatures — {% blocktrans trimmed %} list of all respondent signature images (each row: label, image). Rows without a file are omitted from this list. {% endblocktrans %}

{% trans "Primary respondent — paste into Word" %}

{% trans "Recommended block (image + date on separate lines):" %}

{% verbatim %} 
{{ signature_primary }}
{{ signature_primary_date }}
{% endverbatim %}

{% blocktrans trimmed %} If there is no image, the first line is already the date; the second line repeats the same date (you may hide it with Jinja using signature_primary_has_image if you prefer one line only). {% endblocktrans %}

{% trans "Approver variables" %}

  • approver_signature_primary — {% blocktrans trimmed %} image or approval date from the first approval / workflow-completion event (chronological). {% endblocktrans %}
  • approver_signature_primary_date — {% blocktrans trimmed %}that event’s approval date/time; line below the image.{% endblocktrans %}
  • approver_signature_primary_on_behalf — {% blocktrans trimmed %} bilingual “On behalf of …” when the approver used a delegation; empty for direct assignees. Place below the image or date. {% endblocktrans %}
  • approver_signature_primary_has_image — {% blocktrans trimmed %}True / False.{% endblocktrans %}
  • approver_signatures — {% blocktrans trimmed %} all approval / completion events in order. Each row: label, image (empty when no file), fallback / date (approval date), has_image, on_behalf, on_behalf_docx. {% endblocktrans %}

{% trans "Primary approver — paste into Word" %}

{% trans "Recommended block:" %}

{% verbatim %} 
{{ approver_signature_primary }}
{{ approver_signature_primary_date }}
{{ approver_signature_primary_on_behalf }}
{% endverbatim %}

{% trans "All approvers — loop in Word" %}

{% verbatim %} 
{% for row in approver_signatures %}
{{ row.label }}
{% if row.has_image %}{{ row.image }}{% else %}{{ row.fallback }}{% endif %}
{{ row.date }}
{{ row.on_behalf_docx }}
{% endfor %}
{% endverbatim %}

{% blocktrans trimmed %} Each row is one actor who approved a step or completed the workflow, in chronological order. The image is that user’s primary signature from “My signatures”. If they have no image, row.fallback and row.date are the approval date only. row.label is step label and display name (for example Manager review · jdoe). {% endblocktrans %}

{% trans "Selecting specific approvals" %}

{% blocktrans trimmed %} You can choose which approvals appear in the DOCX without changing MagicForms — only edit the Word template. approver_signatures is a normal Jinja list; rows are in chronological order (when each event was recorded), not necessarily the order of steps in the form designer. {% endblocktrans %}

{% trans "First approval only" %}

{% blocktrans trimmed %} Use approver_signature_primary (and approver_signature_primary_date / approver_signature_primary_on_behalf) — same as the first row when the list is not empty. See the primary approver paste block above. {% endblocktrans %}

{% trans "Fixed position (by index)" %}

{% blocktrans trimmed %} Pick the 1st, 2nd, … approval by index when count and order are always the same: {% endblocktrans %}

{% verbatim %} 
{{ approver_signatures[0].label }}
{% if approver_signatures[0].has_image %}{{ approver_signatures[0].image }}{% else %}{{ approver_signatures[0].fallback }}{% endif %}
{{ approver_signatures[0].date }}
{{ approver_signatures[0].on_behalf_docx }}
{% endverbatim %}

{% blocktrans trimmed %} Use [1] for the second event, and so on. If someone approves out of order or a step is skipped, indices may point at the wrong person. {% endblocktrans %}

{% trans "Filter by step or approver (inside the loop)" %}

{% blocktrans trimmed %} row.label combines the workflow step label and the approver’s display name. Match part of that text in Jinja — use the step name as shown in the workspace, for example: {% endblocktrans %}

{% verbatim %} 
{% for row in approver_signatures %}
{% if 'Manager review' in row.label %}
{{ row.label }}
{% if row.has_image %}{{ row.image }}{% else %}{{ row.fallback }}{% endif %}
{{ row.date }}
{{ row.on_behalf_docx }}
{% endif %}
{% endfor %}
{% endverbatim %}

{% blocktrans trimmed %} Put each step’s block in its own table row or paragraph in Word. You can also match a username if it appears in row.label. {% endblocktrans %}

{% trans "Last approval only" %}

{% blocktrans trimmed %} If your merge supports negative indices, you may use approver_signatures[-1]. Otherwise use loop.last inside the loop: {% endblocktrans %}

{% verbatim %} 
{% for row in approver_signatures %}
{% if loop.last %}
{{ row.label }}
{% if row.has_image %}{{ row.image }}{% else %}{{ row.fallback }}{% endif %}
{{ row.date }}
{{ row.on_behalf_docx }}
{% endif %}
{% endfor %}
{% endverbatim %}

{% trans "What is not available in the template" %}

  • {% blocktrans trimmed %} One MagicForms variable per workflow step slug (for example {{ sig_manager }}) — use index, primary placeholders, or filter on row.label instead. {% endblocktrans %}
  • {% blocktrans trimmed %} Selecting by internal step ID — only the combined label is exposed on each row. {% endblocktrans %}
  • {% blocktrans trimmed %} Rejections in approver_signatures — only approve and workflow-complete events. {% endblocktrans %}
  • {% blocktrans trimmed %} Guaranteed order equal to the workflow designer’s step order — order is by event time. Completing the workflow adds another row like a step approval. {% endblocktrans %}

{% blocktrans trimmed %} Practical layout: fixed cells for known steps → filter with {% endblocktrans %} {% verbatim %}{% if 'Step label' in row.label %}{% endverbatim %} {% blocktrans trimmed %} ; one main signature → approver_signature_primary; full history in order → loop all rows (see above). {% endblocktrans %}

{% trans "Multiple respondent images" %}

{% verbatim %} 
{% for row in submission_signatures %}
{{ row.label }}  {{ row.image }}
{% endfor %}
{% endverbatim %}

{% trans "If the date does not appear" %}

  • {% blocktrans trimmed %} Re-download or preview the merged DOCX/PDF after changing the template or deploying server updates — opening an old downloaded file will not update. {% endblocktrans %}
  • {% blocktrans trimmed %} If the user has a signature image, you must include signature_primary_date or approver_signature_primary_date on the next line; the image placeholder alone does not include a date. {% endblocktrans %}
  • {% blocktrans trimmed %} Use {{ signature_primary_date }}, not {{r signature_primary_date }}, unless you intentionally use RichText. {% endblocktrans %}
  • {% blocktrans trimmed %} For approvers, the submission must have at least one approval or workflow-completion event; otherwise approver placeholders are empty. {% endblocktrans %}

{% trans "Layout tips:" %}

  • {% blocktrans trimmed %} Recommended: loop approver_signatures in a table so the layout adapts when more steps approve. {% endblocktrans %}
  • {% blocktrans trimmed %} Fixed indices (for example {% endblocktrans %} {% verbatim %}{{ approver_signatures[0].image }}{% endverbatim %} {% blocktrans trimmed %} ) only work when event count and order never change. {% endblocktrans %}
  • {% blocktrans trimmed %} Rejections do not add rows to approver_signatures. Completing the workflow adds a row like a step approval. {% endblocktrans %}

{% trans "Inbox, submissions, and search" %}

{% blocktrans trimmed %} The Inbox lists submissions that need attention on a workflow step you are allowed to act on (including via delegation). Open a row to see answers, timeline, notes, merged print output, and attachments. Use Search to locate submissions by reference, email, or text in answers (according to your permissions). {% endblocktrans %}

{% trans "People, delegations, and categories" %}

{% blocktrans trimmed %} People manages user accounts in your scope (and optional HR-style profile fields used for directory display and field pre-fill). Delegations let one staff member cover another’s inbox actions for a date range. Categories group forms on the public portal and in workspace lists. {% endblocktrans %}

{% trans "What respondents see" %}

  • {% trans "A branded public form page (with your header logos if configured)." %}
  • {% trans "After submit: a tracking page with status, step description, and downloads you expose." %}
  • {% trans "“My signatures” lets signed-in users maintain images used in DOCX merges and optionally set a primary." %}
  • {% trans "Related invitations appear in “Forms to complete” when the workflow creates them." %}

{% trans "Practical tips" %}

  • {% trans "Keep internal field names stable once you start using print templates or integrations." %}
  • {% trans "Publish the form before sharing the public link; draft forms cannot be opened or submitted by respondents." %}
  • {% trans "For DOCX, merge once with a test submission to confirm every placeholder resolves (typos show as empty or errors)." %}
  • {% trans "Use PDF as the primary template when you want non-editable distribution; use DOCX when staff need to tweak layout in Word." %}
